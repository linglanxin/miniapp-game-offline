# 小程序游戏离线移植

以用户给出的游戏为目标。优先复用身份和版本已核对的源码、构建及素材，尽量保留关卡、玩法、经济和领奖条件。分享链接、录屏和构建名称提供识别线索。

1. **识别构建。** 解析分享落地页和公开游戏页，查同名开源仓库、开发者发布的网页构建或用户提供的项目包。交叉核对标题、开发者、场景、美术和玩法，区分同一游戏的不同平台及构建。分享码只带跳转信息时，用其他公开证据继续定位。只有录像或模型片段时，给出能复现的范围及缺失项，避免把相似重制标成原版。
2. **镜像资源并跑通基线。** 保存未改副本和清单，确认引擎、入口文件、资源索引、分包和动态资源。先跑过开场至实际关卡，再在断网或同源限制下摸清启动、关卡、领奖及存档依赖。Unity WebGL 用 [构建分析与资源镜像](references/unity-webgl.md)。可用 [清单脚本](scripts/mirror-manifest.py) 比对原始镜像、改包目录和最终压缩包。
3. **按实际调用链修改。** 只在本地副本修改满足用户要求的部分。需要免广告领奖时，定位游戏自己的领奖成功回调和插屏关闭回调，验证资源和状态确实更新。复测重复点击、领奖次数、返回地图和重启读档。背包、商城等入口用新档确认可见可点，避开遮挡地图的引导层。修改编译产物时绑定已核对的构建哈希、检查唯一匹配并保留回退副本。
4. **交付指定平台。** Windows 以稳定的本地地址运行，并带启动方式和同一浏览器配置的存档说明。可从 [本地服务器脚本](scripts/serve-local.py) 开始。Android 按 [APK 打包与验证](references/android-apk.md) 封装，使用固定的包名、签名和本地资源来源。用户要求画面更清晰时，分别确认渲染分辨率、原始贴图大小及性能表现。
5. **用真实行为验收。** 打开最终构建或安装最终 APK，至少确认进入实际关卡、操作有效、目标奖励按需到账、退出奖励界面顺畅、关闭重开后进度保留。记录测试的平台、版本、奖励及关卡范围。区分原版资源完整性、通关覆盖率和平台账号存档兼容性。

默认在工作区内处理源码和本地构建。公开服务、账号、发布渠道和原文件的操作以用户授权的范围为准。测试可以使用独立浏览器来源、模拟器或测试存档。

[《一棍打天下》复用案例](references/tool-evolution-case.md) 收录了分享链接、Unity 奖励回调、导航引导卡死和安卓版验收的具体证据。遇到相似现象时再读。
